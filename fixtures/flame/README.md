# Synthetic flame example

An illustrative 80 kW heptane design fire on the reference layout's 1 ft square
pan, generated by `tools/build_synthetic_flame.py` with seed 20261018. It grows,
puffs, leans and tapers, with occasional detached tips, then burns out. No test
recordings or reconstruction inputs are used. The rig frame equals the plan
frame: x=y=0 at the burner and Z up from the floor.

| File | What it is |
|---|---|
| `voxels/t_<seconds>s.npz` | One frame per 5 s, 0–395 s, e.g. `t_0000055.0s.npz`: `voxels` is M×3 float64, C order, occupied centres in metres; `voxel_size` is 0-d float64. Empty frames are (0, 3). Time exists only in the name. Both NPY members are ZIP-deflated. |
| `volumes.csv` | 20 columns computed from the synthetic frames: volume, exposed-face area and geometric descriptors, defined in the generator docstring. Linked to the burner for the plot. |
| `flame-test.ftp.json` | The reference plan with a `reconstructedFlame` linking `voxels/` and the burner linking `volumes.csv`. Format 1.4.0. |
| `flame-test.fvs` | Gzipped packed frames for the bundled Example and shared-page tests. |
| `expected.json` | The manifest, packed-bytes digest and surface-cell digest the Python reader computes on `voxels/`; the TypeScript reader is held to them. |
| `check-cases.json` | Placement and CSV-provenance check cases run by both test suites. |

The grid is 192³ over a 3 m cube centred at (0, 0, 1.4) m: x/y centres are
`linspace(-1.5, 1.5, 192)`, z centres are that array plus 1.4 m. Pitch is 3/191 m;
stored `voxel_size` is 3/192 m. The first occupied centre is at
z=0.009947643979057563 m. There are 948,705 occupied cells over the run, at most
31,013 per frame; 215,156 surface cells are drawn (22.7%). The NPZ total is
2,817,087 bytes; the packed stream is 288,028 bytes, or 65,024 bytes gzipped.

Open **flame-test.ftp.json** in the editor and press play. Select the burner for
the volume plot, which follows the same clock. From the repository root:

```text
python tools/build_synthetic_flame.py
python tools/build_flame_fixture.py
python tools/build_linked_fixture.py
```

The flame builder regenerates the plan, `.fvs` and `expected.json` using the
Python reader (including little-endian uint16 surface-cell digests). Run both
test suites after regenerating; they pin manifests, packed bytes and surfaces.

See [the design](../../docs/flame-playback-design.md) for the format and the
reasoning, and CONVENTIONS.md section 11 for the rules.
